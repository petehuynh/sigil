1 Foundations

Sigil is a formally specified language for inter-agent dialogue. Every Sigil message is a bracketed expression with a declared type, a sender, an optional receiver, and a content body. The grammar is documented here; the recursive-descent parser at sigil_core/parser.py is the canonical interpreter; the test suite at packages/sigil-core/tests/ is the executable spec.

The design is deliberately small. Nine message types Q · A · N · C · E · P · V · O · X, eleven precedence levels, thirty-one AST node classes. A language that can be held in a paper.

1.1 Message structure

Every Sigil expression is a message, written either in parenthesized form or in bracketed form. The two are equivalent at the AST level; the lexer normalises them.

Definition 1.1 · Message A message is a triple ⟨type, head, content⟩ where type is one of the nine message types, head is a sequence of key-value pairs (the message metadata), and content is a sequence of atoms, key-value pairs, scopes, lists, and sub-messages.

The nine message types: Q Query, A Answer, N Negotiate, C Command, E Error, P Propose, V Vote, O Observe, X Execute. The closed set is locked at v0.5.0; expansion requires a SIP.

1.2 Atoms and literals

An atom is an indivisible value: a number, a string, an identifier, an entity reference. The lexer at sigil_core/lexer.py recognises six atomic categories.

  • Number. Integer (42), float (3.14), negative (-7). Mono numerals throughout.
  • String. Double-quoted ("hello") or single-quoted ('hello'); equivalent at the AST level.
  • Identifier. Alphanumeric with hyphens; e.g. agent-42.
  • Entity reference. The @ sigil names an entity: @singapore, @ns:name.
  • Qualified name. Colon-separated for namespacing: user:42, ai:src:cmd.
  • Key-value pair. A qualified name followed by a value (see §1.3).

1.3 Key-value pairs and qualified names

Sigil's primary structural primitive is the key-value pair. When a colon-separated identifier is followed by a value, the AST records a KeyValue node with key and value children.

2 Types

Sigil's type system is dependent. Pi types let a message say "for any n, a vector of size n"; Sigma types let it say "a pair of an n and such a vector"; Refinement types let it say "a positive integer." The foundations are Martin-Löf's Martin-Löf 1984; the categorical groundwork is Mac Lane's Mac Lane 1971.

2.1 Pi types (dependent functions)

Written Π(n:Nat) Vec(n) in the surface syntax, or Pi(n:Nat) Vec(n) in the ASCII alternative. The parser accepts both; the serializer canonicalises to the Unicode form.

Π-form · π-formation

Γ ⊢ A : Type Γ, x:A ⊢ B(x) : Type Γ ⊢ Π(x:A) B(x) : Type
Theorem 2.1 · Π-type round-trip For every well-typed Sigil expression e containing Π-binders, parse(serialize(parse(e))) = parse(e) as ASTs. test_dependent_types.py:42

2.2 Sigma types (dependent pairs)

Written Σ(n:Nat) Vec(n): a pair of a natural number and a vector of that size. Dual to Π; together they form the type-theoretic core. See Martin-Löf 1984 §5.

2.3 Refinement types

A scope with a predicate: {x:Int | x > 0} reads as "an integer x such that x is positive." The parser checks the predicate is well-formed; it does not evaluate it. Evaluation is the type-checker's job; the type-checker ships as a separate package on Developer Pro.

Lemma 2.3 · Refinement subtyping If P(x) → Q(x) in the ambient logic, then {x:A | P(x)} <: {x:A | Q(x)}. The implication direction is opposite the subtyping direction by classical refinement-type semantics.

3 Probability

Probability is syntax, not metadata. A Sigil expression can carry a probability qualifier on any assertion; the qualifier is parsed, type-checked, and round-tripped like any other expression.

3.1 Named distributions

Sigil v0.5.0 ships with a closed set of named distributions: Normal(μ, σ), Beta(α, β), Gamma(k, θ), Bernoulli(p), Categorical(p₁, …, pₙ), Dirichlet(α₁, …, αₙ). The named-distribution registry is extensible via SIP.

3.2 Bayesian update

The ∝ operator (proportional-to) is the syntactic Bayesian update: P(H|E) ∝ P(E|H) · P(H). The parser does not compute the normalisation; the type-checker does (Developer Pro), and the inference engine does (out of scope for the language). The grammar carries the semantics; the runtime carries the computation.

4.1 Operator precedence

Eleven precedence levels, pulled verbatim from sigil_core/parser.py. Level 1 is the lowest binding (logical OR); level 11 is the tightest (path access). The full table renders on the home page as a separate signature.

4.2 Round-trip serialization

The serializer at sigil_core/serializer.py is deterministic. For every well-formed AST t, parse(serialize(t)) = t — equality as ASTs, not as strings. This is the property that makes Sigil messages content-hashable: two agents comparing the same message produce the same SHA-256.

Theorem 4.2 · Determinism of serialization Let t be a well-formed Sigil AST. Then serialize(t) is the unique canonical string s such that parse(s) = t and serialize(parse(s)) = s. The proof is by structural induction on t; the test suite test_round_trip.py exercises all 31 AST node classes. HoTT 2013 §2 on identity-types motivates the equality.

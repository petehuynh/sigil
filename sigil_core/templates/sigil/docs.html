Documentation

Sigil in 10 minutes.

From pip install to your first parsed message — in five examples. Every snippet here validates against the shipped parser. If a block fails to parse for you, the package is broken; file an issue.

⊢ Tested against v0.5.0 · ⊢ 298 / 298 ✓ · ⊢ Pure Python · no dependencies

01Install

Install the package.

Pure Python, no C extensions, no Rust FFI. The parser, the serializer, the builder, and the 298-test suite ship inside one wheel. Python 3.10 or newer.

$pip install sigil-core
Successfully installed sigil-core-0.5.0
$python -c "import sigil_core; print(sigil_core.__version__)"
0.5.0

⊢ verified · packages/sigil-core/pyproject.toml

02Parse a message

Parse your first Sigil message.

Every Sigil expression is a message — a bracketed payload with a type, a sender, and a content body. The simplest message is a Query; the parser returns an AST you can inspect.

The AST is a tree of nodes from sigil_core/ast_nodes.py — Message, KeyValue, Identifier, StringLiteral, and 27 more. Every node carries a stable shape; every parse is deterministic.

⊢ verified · test_parser_basic.py:18

03Build and round-trip

Build a message in Python. Serialize it back to Sigil. Parse it again.

The builder API gives you typed constructors for every AST node. The serialize function is deterministic — two agents building the same message produce the same string and the same content hash.

This is the property that makes Sigil messages content-addressable. Two agents in different processes — different machines, different jurisdictions — produce the same SHA-256 for the same logical message. There is no key-order drift, no whitespace ambiguity, no encoding surprise.

⊢ verified · test_round_trip.py — all 31 AST nodes

04Dependent types

Constrain values with the type that describes them.

Sigil ships Π (Pi), Σ (Sigma), and Refinement types in v0.5.0. They are not runtime assertions; they are part of the grammar. The parser builds them into the AST; the type-checker (Developer Pro) evaluates them.

The ASCII alternatives are Pi(n:Nat) Vec(n) and Sigma(n:Nat) Vec(n). The parser accepts both; the serializer canonicalises to the Unicode form. Either is valid input.

⊢ verified · test_dependent_types.py

05Probability

Attach a probability to an assertion. Parse the result.

Named distributions are first-class. Beta(94, 6) is not a string in a JSON field — it is a parseable expression with a type, a content hash, and a round-trip serialization. The ~ operator reads as "is distributed as."

The closed v0.5.0 distribution registry: Normal, Beta, Gamma, Bernoulli, Categorical, Dirichlet. New distributions extend the registry via SIP — the spec is the gate.

That is the ten-minute loop. Install, parse, build, type, qualify. Everything else in the language is composition of these five moves.
